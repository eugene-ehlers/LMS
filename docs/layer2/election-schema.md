# Election schema

Decision 19. One organisation row, and an optional product row that overrides it. A product field left null inherits the organisation. A null at both levels fails closed when the row is resolved, except the residual write-off threshold, which fills R100. The list routes return the nulls so staff can see what is still unset.

The vocabulary is the constants already published by `lms_config.locked`. This layer does not add a second spelling.

The Python record is `lms.staff.elections.ElectionValues`. The organisation and product tables gain the two campaign fall-away columns in `db/migrations/0008_layer2_staff.sql`. The other columns already exist on `lms.cfg_organisation_settings` and `lms.cfg_product_terms`.

| Field | Allowed values | Fail-closed resolve |
| --- | --- | --- |
| `vat_on_rand_maxima` | `exclusive`, `inclusive` | Required |
| `late_disbursement` | `adjust_instalment`, `keep_instalment` | Required |
| `partial_prepayment` | `shorten_term`, `drop_instalment` | Required |
| `interest_on_deferred_initiation` | `none`, `permitted` | Required. Storing `none` is the provider's choice of the decision 10 default |
| `repo_rate_fall` | `contract_rate`, `lower_of_contract_and_cap` | Required. There is no platform default |
| `in_duplum_trigger` | `contractual_breach`, `collections_default` | Required. Resolved by `resolve_in_duplum_trigger` |
| `residual_write_off_threshold_cents` | Integer cents, zero or greater | An unset organisation or product value fills R100 (10 000 cents). A stored value, including zero, wins |
| `campaign_fall_away_choice` | `falls_away_on_default`, `does_not_fall_away` | Required. The choice and the trigger are one pair |
| `campaign_fall_away_trigger` | `contractual_breach`, `collections_default`, or null | Required only when the choice is `falls_away_on_default`. Null when the choice is `does_not_fall_away` |

A product that sets `campaign_fall_away_choice` replaces the organisation choice and the organisation trigger together. It does not keep the organisation trigger beside a product choice.

## Residual threshold

Decision 19 gives this threshold a platform default of R100. An unset organisation or product value fills 10 000 cents. `resolve_elections` calls `resolve_residual_threshold_cents`. A stored zero remains zero. The list routes still return a stored null so staff can see that the organisation has not chosen a different amount.

## Campaign row

The campaign is not an election row. It is `lms.cfg_campaign` / `lms.staff.campaigns.Campaign`.

| Column | Type |
| --- | --- |
| `campaign_id` | Identifier generated by the LMS |
| `organisation_id` | Opaque Enigma organisation id |
| `product_id` | Opaque product id, or null |
| `start_date`, `end_date` | Johannesburg dates, `start_date <= end_date` |
| `base_rate`, `discount_rate` | Decimal fractions, each `>= 0`. The discount may be greater than the base |
| `net_rate` | Result of the net-rate call described in the routes. Not a column the client sends. The SQL table does not store it separately; the read path computes it with the same function |
| `fall_away_choice`, `fall_away_trigger` | Same pair as the election |
| `initiation_fee_discount_cents`, `service_fee_discount_cents` | Integer cents, `>= 0` |
| `version` | Starts at 1. Edit and end increment it |

`lms.election_snapshot` still requires `discount_rate <= base_rate`. A campaign whose discount exceeds the base is stored on `lms.cfg_campaign` and on the decision-intake copy. It is not written onto `lms.election_snapshot`. Doing so would need a schema change in the booking snapshot, which would be a Layer 0 change.

## What resolve does not call

`resolve_customer_settings` also demands leniency, a payment threshold, a day count, and a campaign rate pair. The decision 19 resolve does not. It does call `resolve_in_duplum_trigger`, which fails closed, and `resolve_residual_threshold_cents`, which fills R100 when both levels are null.
